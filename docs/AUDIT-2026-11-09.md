# Security & SEO Audit — Wheel Werks website

**Date:** 2026-11-09 · **Scope:** repo `JamesBaker528/wheel-werks` @ `bd30786`, live https://wheel-werks.vercel.app, legacy https://www.wheelwerks.net
**Method:** code review, non-destructive live probes (~25 API requests, fake data only, no emails sent — delivery not configured), header capture per route type, full crawl of 12 pages, all 4,922 legacy URLs replayed against a local production build, Lighthouse 12 (local), Vercel project settings via API.

> **Remediation status (same day, commit after `bb612f4`):** all code-level findings fixed and deployed — see [Remediation](#remediation) at the end. Remaining items need the owner or a later major upgrade.

## Executive summary

**Overall risk: Medium — not a launch blocker for a brochure site, but the quote form must not be switched on until S1–S3 are fixed.**

The site is in good shape on fundamentals: strict security headers on every route, no secrets in client bundles, no exposed source or build files, preview deployments behind Vercel Authentication, the image optimizer rejects remote URLs, no open redirects, and all JSON-LD is safely escaped. SEO foundations are solid: unique titles/descriptions, one H1 per page, no heading skips, complete alt text, valid LocalBusiness/Service/FAQ/Breadcrumb schema, and **4,917 of 4,922 legacy URLs 308-redirect to a live page**.

The weak spot is **abuse protection on the quote API**. The rate limiter does not work on Vercel (10+ requests accepted against a 5/10-min limit), the bot-timing check is trivially bypassed, and there is no CAPTCHA. Once email delivery is enabled, the form could be used to flood the shop's inbox. On the SEO side, the **vercel.app domain is currently fully indexable with self-referencing canonicals**, which risks a duplicate-content split with wheelwerks.net at cutover.

## Verified OK

- Headers on HTML, API, static chunks, `/media`, `/video`, `/_next/image`, 404: CSP, HSTS, `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`, COOP. API responses `no-store`; static chunks `immutable`.
- Cross-site POST → 403; PUT/DELETE → 405; malformed JSON/non-multipart → 400; Zod validation and bad-file rejection work; error bodies leak no internals.
- No server secrets (`RESEND`, `UPSTASH`, `TURNSTILE_SECRET`, `QUOTE_*`) in `.next/static`; only `NEXT_PUBLIC_SITE_URL` and `NEXT_PUBLIC_TURNSTILE_SITE_KEY` are public.
- `/.env`, `/.git/config`, `/package.json`, `/next.config.ts`, `/src/...`, `/_next/server/...` → 404.
- `/_next/image` refuses remote URLs (400) — no SSRF/open proxy.
- Legacy redirects and middleware have fixed destinations — no open redirect.
- Single `dangerouslySetInnerHTML` (JSON-LD) escapes `<`; `?service=` is allow-listed; `?brand=` only populates a React-escaped input.
- All `target="_blank"` links carry `rel="noopener noreferrer"`.
- Email builder: HTML-escaped body, CR/LF stripped from subject, `reply_to` is a validated email, attachment names server-generated.
- Vercel: preview deployments protected by Vercel Authentication; Git fork protection on; directory listing off; Vercel firewall throttles request bursts (observed during this audit).
- Prior `/tires`↔`/Tires` redirect loop is fixed.

## Domain cutover checklist (www.wheelwerks.net)

1. Vercel → Domains: add `www.wheelwerks.net` (primary) and `wheelwerks.net` → 308 to www. Update DNS as Vercel instructs; wait for SSL.
2. Set `NEXT_PUBLIC_SITE_URL=https://www.wheelwerks.net` (Production) and redeploy — this switches canonicals, sitemap, robots and JSON-LD `@id` together.
3. Redirect `wheel-werks.vercel.app` → www (Vercel domain redirect), or keep the `X-Robots-Tag: noindex` from E1 on `*.vercel.app`.
4. Verify on the live domain: `/sitemap.xml`, `/robots.txt`, canonical tags, JSON-LD `@id`, a sample of legacy URLs (`/Services/Wheel-Repair`, `/Tires/...`, `/About/Photo-Gallery/ID/54`).
5. Search Console: verify the domain property, submit the sitemap, use the URL Inspection tool on the home and service pages; keep the old sitemap URL redirecting.
6. Update the Google Business Profile website link and the Facebook/Instagram/Yelp profile links.
7. Re-run PageSpeed Insights and the Rich Results Test on the production domain.
8. Monitor Search Console Coverage and 404 reports for 4–6 weeks; add redirects for anything unexpected.
